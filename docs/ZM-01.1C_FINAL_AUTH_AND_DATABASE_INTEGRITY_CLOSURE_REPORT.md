## Section C: Workstream B — Supabase Client Separation & User Authentication Isolation

### Architectural Pattern
- **Problem Resolved:** Previously, `getSupabaseAdminClient()` (using `SUPABASE_SERVICE_ROLE_KEY`) was invoked directly for user credential validation via `signInWithPassword`. In Supabase JavaScript client, `signInWithPassword` mutates the client instance's internal session state. Calling this on a shared administrative client created severe concurrency risks and potential session pollution across requests.
- **Factory Implementation (`src/lib/supabase/index.ts`):**
  ```typescript
  export function createUserAuthClient(): SupabaseClient | null {
    if (!isSupabaseConfigured()) return null;
    return createClient(
      process.env.NEXT_PUBLIC_SUPABASE_URL!,
      process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
      {
        auth: {
          persistSession: false,
          autoRefreshToken: false,
          detectSessionInUrl: false,
        },
      }
    );
  }
  ```
- **Separation of Concerns:**
  - `createUserAuthClient()`: Used exclusively for user-facing authentication flows (`signInWithPassword`, `signUp`, `resetPasswordForEmail`). Each call creates an isolated, ephemeral instance with public anonymous privileges. Sessions are never persisted to disk or shared memory.
  - `getSupabaseAdminClient()`: Restricted exclusively to server-side administrative operations (bypassing RLS for system provisioning, marking users confirmed, user deletion). Never holds user credential state.
- **Empirical Evidence:**
  - Test 5 in `tests/phase1-final-auth-integrity.test.ts` validates concurrent login for distinct users (`student@zealosh.com` and `vishnu@zealosh.com`), confirming both succeed concurrently with distinct tokens, distinct session IDs, and zero cross-talk.

## Section D: Workstream C — Password Recovery, Token Versioning & Session Invalidation

### Lifecycle & Revocation Mechanics
1. **Password Reset Request (`/api/auth/password-reset/request`):**
   - Candidate provides email. Generates single-use token (`rst-...`) with 15-minute expiration in `db.passwordResetTokens`.
2. **Password Reset Confirmation (`/api/auth/password-reset/confirm`):**
   - Validates token, checks expiration, enforces 10+ character password complexity.
   - Calls `db.confirmPasswordReset(token, newPassword)`:
     - Updates `user.passwordHash`.
     - Advances `profile.tokenVersion = (profile.tokenVersion || 1) + 1` and `user.tokenVersion = profile.tokenVersion`.
     - Revokes all active user sessions: sets `session.revoked = true` for all matching `session.userId === user.id` in `db.userSessions`.
     - Records `PASSWORD_RESET_COMPLETED` audit event.
   - In Supabase mode: synchronizes new password via `adminClient.auth.admin.updateUserById(userId, { password })`.
3. **Token Version Verification in `src/lib/auth/admin-guard.ts`:**
   - Decodes JWT and inspects `payload.tokenVersion`.
   - Compares against current `db.profiles.get(payload.userId)?.tokenVersion`.
   - If `payload.tokenVersion < currentVersion`, the request is immediately rejected with HTTP 401 Unauthorized (`Session invalidated due to credential update. Please log in again.`).
   - Re-issuance with updated version succeeds.

## Section E: Workstream D — Multi-Factor Authentication (MFA / TOTP) Architecture & Enforced Guard

### Engine Capabilities & REST Endpoints
1. **Factor Enrollment (`POST /api/auth/mfa/enroll`):**
   - Authenticated user initiates TOTP enrollment.
   - Generates unique `factorId` (`mfa-totp-...`), RFC 6238 compatible secret (`JBSWY3DPEHPK3PXP...`), `otpauth://totp/Zealosh:...` URI, and QR code URL.
   - Factor stored with status `'unverified'` in `db.mfaFactors`.
2. **Challenge Creation (`POST /api/auth/mfa/challenge`):**
   - Accepts `{ factorId }`.
   - Generates unique challenge (`mfa-ch-...`) with 5-minute expiration (`Date.now() + 5 * 60 * 1000`) in `db.mfaChallenges`.
3. **Challenge Verification (`POST /api/auth/mfa/verify`):**
   - Accepts `{ challengeId, code }`.
   - Validates 6-digit TOTP code, marks challenge `verified = true`, promotes factor status to `'verified'`, sets `profile.mfaEnabled = true`, and returns `{ verified: true, assuranceLevel: 'aal2' }`.
   - Records `MFA_FACTOR_VERIFIED` audit event.
4. **Factor Unenrollment (`POST /api/auth/mfa/unenroll`):**
   - Authenticated user removes factor. If zero verified factors remain, automatically sets `profile.mfaEnabled = false`.
5. **Admin Guard Enforcement (`src/lib/auth/admin-guard.ts`):**
   - If `profile.mfaEnabled === true`:
     - Checks if request provides MFA proof via token claims (`payload.mfaVerified === true` or `payload.aal === 'aal2'`) or trusted header (`x-mfa-verified: true`).
     - If unverified, rejects request with HTTP 403 Forbidden:
       `{ success: false, error: 'Forbidden: Multi-factor authentication (MFA) required', code: 'MFA_REQUIRED' }`

## Section I: Workstream H — Configurable Document Upload Validation & Positive Bounds

### Validation Guardrails in `src/lib/storage/document-validation.ts`
- **Positive Bounds Checks:**
  - `getMaxDocumentSizeBytes(settings)`: Ensures that configured `maxDocumentSizeBytes` is an integer strictly $> 0$ and $\le 100\text{ MB}$. If non-positive, negative, or invalid, falls back safely to `DEFAULT_MAX_DOCUMENT_SIZE_BYTES` ($25\text{ MB}$).
  - `validateDocumentUpload(doc, index, maxSizeBytes)`:
    - Strictly rejects file sizes $\le 0$, negative, or `NaN` with: `Document <name> specifies an invalid non-positive file size. Must be a positive integer.`
    - Validates magic byte signatures: `%PDF-` for PDF, `\x89PNG\r\n\x1a\n` for PNG, `\xFF\xD8\xFF` for JPEG, `RIFF...WEBP` for WebP.
    - Strictly rejects executable formats (PE/MZ, ELF, script shebangs `#!`, Mach-O, Java bytecode).
    - Sanitizes filenames against path traversal (strips null bytes, directory separators, consecutive dots).

## Section K: Workstream J — Monotonic Collision-Safe Application Numbering

### Algorithm & Concurrency Protection
- **Format:** `APP-YYYY-XXXX` (e.g. `APP-2026-0001`, `APP-2026-0002`).
- **Generation:**
  - Extracts current calendar year (`new Date().getFullYear()`).
  - Scans existing applications matching `APP-YYYY-` to find current maximum sequence integer.
  - Increments atomically to prevent sequence gaps or collisions.
  - Zero-padded to 4 digits minimum (`padStart(4, '0')`).
